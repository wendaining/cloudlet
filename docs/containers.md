# 容器生命周期与公开访问

项目所有者和 developer 成员可以通过共享管理 API 从不可变镜像摘要创建 HTTP 容器。平台完成容量准入、真实 Docker 启动与 HTTP 就绪检查后，才为项目域名注册 Gateway 路由。项目成员可以查询容器配置、执行与 Operation 结果，所有者和开发者可以停止、再次启动或删除容器。

## 运行配置

`make dev` 为每个实例生成 `containers` 配置，并与 Worker 共享主机预算和项目初始配额。直接运行 Go 服务时，按 [本地开发与服务器部署](development.md) 配置管理数据库、实例、平台密钥和静态站点目录，并在 JSON 配置中声明：

```json
{
  "containers": {
    "host_id": "local",
    "host_budget": {
      "cpu_millis": 4000,
      "memory_bytes": 4294967296,
      "instances": 4
    },
    "project_quota": {
      "cpu_millis": 4000,
      "memory_bytes": 4294967296,
      "instances": 4
    }
  }
}
```

预算须包含至少 1000 CPU 毫核、256 MiB 内存与一个实例。项目首次创建容器时登记配置中的初始配额，已有配额保持原值。同时配置 Worker 与容器运行时，两者的 `host_id`、主机预算和项目配额必须一致，否则服务终止启动。

初始化验证配置、Docker Linux 引擎、PostgreSQL 控制锁与路由快照。依赖失败时终止启动。控制连接失效时拒绝新请求，已有容器继续运行。容器执行固定使用 256 个进程和 1024 个文件句柄上限，CPU 与内存按请求声明申请并限制。

## 管理 API

```text
POST /api/v1/projects/{projectID}/containers
Content-Type: application/json
Idempotency-Key: first-container
```

```json
{
  "name": "web",
  "image": "nginxinc/nginx-unprivileged:1.29.3-alpine@sha256:5aea7cc516b419e3526f47dd1531be31a56a046cfe44754d94f9383e13e2ee99",
  "port": 8080,
  "hostname": "container.localhost",
  "cpu_millis": 500,
  "memory_bytes": 134217728,
  "user": "101:101",
  "health_check_path": "/",
  "health_check_timeout_ms": 15000,
  "data_volume": {
    "mount_path": "/data",
    "directory": "state"
  }
}
```

镜像必须包含 `repository@sha256:digest` 形式的不可变摘要，仅使用标签的引用返回 400。容器名称由小写字母、数字和单个连字符分隔的名称段组成，最多 63 个字符。域名不包含端口，平台注册根路径路由。`user` 必须是非 root 身份，省略时使用 `1000:1000`。`command` 覆盖镜像命令，`env` 使用 `KEY=value` 形式，请求体总大小最多 64 KiB。

`data_volume` 声明一个可写数据卷。平台按实例、项目和容器名称生成稳定的 Docker 卷名，挂载到 `mount_path`，并在卷内创建交给 `user` 所有的单段目录 `directory`；实际可写路径为 `mount_path/directory`。声明卷时 `user` 必须使用数字形式的非 root 用户和组，例如 `101:101`。卷名不接受客户端指定，同一容器停止后再次启动沿用同一卷；其他容器不能取得该卷。删除容器时同时删除声明的卷。

创建流程先登记幂等 Operation 与不可变执行配置，再按摘要准备镜像、创建或核对声明卷、预留主机和项目容量、创建并启动真实容器。容器实际发布的回环端点在声明的截止时间内返回 200 至 399 后，平台在同一事务中登记活动执行、容器标识和域名路由。Gateway 应用已提交快照后返回 201，响应包含 `id`、`execution_id`、`operation_id`、镜像摘要、容器标识、实际端点与操作终态。`Location` 指向容器查询地址。

同一容器名称的相同幂等键与请求返回同一结果，已结束操作的重试返回 200，并保留成功或失败终态。更换请求内容时返回 409。容器已有活动执行或未完成创建时返回 409。已提交活动执行后的快照同步或收尾失败，可以通过重复原请求完成。

请求格式无效返回 400，未登录返回 401，查看者创建返回 403，非项目成员返回 404。域名冲突或数据卷声明与已有配置不一致返回 409。数据卷创建失败、镜像准备、容器启动或 HTTP 就绪失败返回 422，容量不足返回 429。确定失败时先停止并删除已创建的容器，确认清理后释放容量，再记录失败原因。清理失败时保留容量和待处理执行，避免平台超额分配。名称或域名冲突发生在容器执行记录写入前时，失败原因同样按 Operation 保存，同一幂等键重试返回原冲突结果。

```text
GET /api/v1/projects/{projectID}/containers/{containerID}
```

项目成员可以查询容器配置、最近执行与操作结果。非成员返回 404。

## 停止、再次启动与删除

三个生命周期操作都需要 `Idempotency-Key`，只有项目所有者和 developer 可以调用：

```text
POST   /api/v1/projects/{projectID}/containers/{containerID}/stop
POST   /api/v1/projects/{projectID}/containers/{containerID}/restart
DELETE /api/v1/projects/{projectID}/containers/{containerID}
```

停止先撤销该容器的项目路由并应用 Gateway 快照，使新请求立即停止进入容器；然后停止并删除真实 Docker 容器，确认删除后释放容量，最后把执行和容器记录为 `stopped`。停止保留声明的数据卷。停止失败时保留容器、卷和容量，重复同一幂等键可以继续清理。已经停止的容器再次停止返回当前状态。

再次启动从最近保存的执行配置创建新的执行序号，重新核对并挂载同一数据卷，准备镜像、预留容量、启动真实容器并执行 HTTP 就绪检查；就绪后重新注册域名路由。新执行读取到卷中的原数据。卷缺失时拒绝启动并保留失败原因。已经完成的再次启动使用同一幂等键重试返回当前状态；新的再次启动请求在容器仍为活动时返回 409。容量不足返回 429，镜像或就绪失败返回 422，容器状态不允许操作返回 409。

删除先按停止流程撤销路由、停止 Docker 容器并释放容量，再删除声明的数据卷，确认卷不存在后删除执行记录和逻辑容器。删除成功后查询返回 404，公开域名不再转发到该容器，卷也不再存在。重复同一幂等键的删除返回 204。容器处于 `pending` 时拒绝停止、再次启动或删除。

## 控制器重启接管

控制器启动时先取得主机控制器会话锁、写入主机容量并恢复 Gateway 路由快照，再按 PostgreSQL 中的活动执行、容量预留归属和 Docker 标签逐个核对受管理容器，核对完成后才开始接受请求。启动接管不会创建副本。

每个活动执行使用环境、项目、资源和执行序号重新查找 Docker 容器。运行中的容器按镜像摘要、CPU 与内存上限、进程与文件句柄限制、数据卷和已安装文件摘要核对后直接接管，执行标识与容器标识保持不变；实际发布的回环端点与已记录目标不一致时，在同一事务中更新执行目标、项目路由目标和路由快照版本，再应用 Gateway。数据卷内容保持不变。

容器被外部停止时启动一次并完成 HTTP 就绪检查，成功后恢复路由；就绪失败时撤销路由、停止并删除容器、释放容量，记录失败原因。启动命令本身失败时终止本次启动并保留记录与容量，由维护者核对。记录为活动但 Docker 容器已不存在时同样不创建副本，撤销路由、释放容量并把容器记录为 `failed`，保留声明的数据卷，之后可以通过再次启动创建新的执行。观测 Docker 失败或执行配置与容器不一致时终止启动，保留原有记录与容量，由维护者核对。异常退出后的恢复预算、Docker 事件和缺少元数据的遗留容器由 #120、#121 等后续任务接入。

## 验收

运行 `make dev`，使用项目所有者或 developer 会话发送上述创建请求。响应成功后通过 Gateway 访问声明的域名，核对容器返回的 HTTP 内容；读取 `Location`，用 Docker inspect 核对容器标识、归属标签、镜像摘要、资源限制、非 root 用户和回环端口。

使用仅含标签的镜像引用确认返回 400；使用不存在的镜像摘要确认镜像准备失败返回 422、Operation 失败且没有留下 Docker 容器。再使用有效镜像和会立即退出的命令创建另一个容器，确认返回 422、Operation 失败、容器被删除且项目容量恢复。使用超过项目配额的 CPU 创建容器，确认返回 429 且没有创建 Docker 容器。

向容器的 `mount_path/directory` 写入文件，确认 Docker volume 存在且归属标签正确。再通过生命周期接口停止容器，确认公开域名返回 404、Docker 容器已删除、数据卷保留且项目容量释放；使用同一幂等键重复停止，确认返回相同 `stopped` 状态。再次启动容器，确认获得新的执行序号和 Docker 容器、读取到停止前写入的原数据、公开域名恢复响应且容量重新占用。最后删除容器，确认公开域名返回 404、查询返回 404、Docker 容器和数据卷均不再存在且容量释放；重复同一幂等键删除返回 204。

重启接管验收记录容器标识、执行标识、卷中数据和公开入口，然后重启管理进程。恢复后确认同一 Docker 容器仍在运行、执行标识不变、卷数据仍可读取、公开域名继续响应，且 Docker 中该资源只有一个容器。再分别验证：外部停止容器后重启管理进程会启动同一容器并恢复路由；删除 Docker 容器后重启管理进程不会创建副本，公开域名返回 404、容量释放、容器记录为 `failed` 且数据卷保留。

自动验证命令与覆盖范围见 [测试说明](testing.md#容器重启接管验收)。PR 审查者亲自执行创建、公开访问、停止、再次启动、删除、重启接管、Docker 核对和失败清理，并记录环境、实际操作和结果后批准。

## 当前限制

- 当前支持一个声明式可写数据卷。平台生成卷名并写入环境、项目、资源和卷类型归属标签；同一卷只允许一个运行中的执行，其他容器不能取得该卷。只读卷挂载由 #119 交付。
- 停止和删除只处理当前活动执行；控制器启动接管运行中的容器，异常退出后的恢复预算、Docker 事件和缺少元数据的遗留容器清理由 #120、#121 等后续任务接入。
- 项目级数据卷隔离和跨项目访问限制由 #48 继续验证；当前通过平台生成卷名和归属标签拒绝其他项目使用已有卷。
- 容器端口发布在宿主回环地址，由同一主机上的 Gateway 转发。容器管理 API 尚未切换到项目网络；项目网络生命周期、归属标签校验和删除保护已在 `internal/containers` 提供，接入由后续任务完成。
- 修改镜像或配置产生新执行、活动版本切换和旧执行排空尚未接入。再次启动复用最近保存的配置。
