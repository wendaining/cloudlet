## 二、选题

Cloudlet 为需要在单台 Linux 服务器上交付小型云应用的个人开发者与小型团队，提供统一的应用发布、运行控制和公网访问入口。

平台围绕 Workers、Durable Objects、Containers 和 Browser Run 管理计算资源。用户通过管理界面、CLI、MCP 或 HTTP API 完成登录、项目授权、部署、查询、停止与删除。Gateway 根据已提交的路由配置向外部提供访问入口。

选题覆盖三类用户，项目所有者管理成员和预算，开发者创建与发布资源，观察者查看获授权的状态和日志。平台保持项目隔离，执行资源由实际运行时承载，Go 控制器负责元数据、协调和恢复。

| 判断项 | 当前结论 |
| --- | --- |
| 业务背景 | 小型团队需要运行应用，却缺少一套操作一致、状态可恢复的平台 |
| 产品价值 | 减少在不同运行时工具之间切换的操作，集中管理发布、权限和可用状态 |
| 差异机会 | 面向单台服务器优化，同时保持项目隔离、不可变部署和执行状态恢复 |
| 外部集成 | 拟提供部署与运行状态 Webhook，向 Slack 或 HTTPS 端点发送通知 |
| 技术风险 | 四核四 GiB 预算下的运行时容量、DO 数据交接和跨平台 Docker 行为 |

平台规划三类用户角色，课程要求至少包含一个外部集成点。项目拟以部署状态 Webhook 作为外部集成点，并通过真实接收端验证签名、重试和失败记录。

## 四、现状流程

根据现有设计，目标用户需要完成以下工作。

| 阶段 | 用户操作 | 平台职责 |
| --- | --- | --- |
| 准备 | 提供代码、镜像、绑定和资源要求 | 验证项目权限、产物摘要与容量 |
| 发布 | 创建新的 Deployment | 保存不可变版本，完成预检和就绪检查 |
| 激活 | 确认启用新版本 | 在事务中切换活动版本和 Gateway 路由 |
| 运行 | 查询资源、操作和运行状态 | 从实际运行时取得观测结果 |
| 恢复 | 处理重启、故障或交接 | 按元数据和真实执行状态接管或清理 |
| 访问 | 通过项目域名调用服务 | 使用已提交的快照转发请求 |

这条流程把发布、状态和访问统一到一套管理入口。对个人开发者，它可以减少手工整理配置的工作。对维护者，它可以提供跨项目的权限和容量边界。

## 五、调研发现

| 编号 | 初始发现 | 依据 | 可信程度 |
| --- | --- | --- | --- |
| F1 | 发布过程涉及代码产物、运行时、绑定、预检、激活和路由，缺少统一视图会增加排查难度 | [平台设计](../platform-design.md) | 设计确认，待访谈 |
| F2 | 单机平台必须知道实际执行状态，控制器重启后不能只依赖内存记录 | [执行环境设计](../runtime-design.md) | 设计确认，待故障回顾 |
| F3 | 四核四 GiB 预算会限制浏览器和多个运行实例，应在申请资源前预留容量 | [实施清单](../development-deployment-checklist.md) | 容量目标，待负载验证 |
| F4 | 跨项目访问必须同时检查资源授权和绑定归属，管理日志不能泄露 Secret | [平台设计](../platform-design.md) | 设计确认，待安全场景确认 |
| F5 | 用户需要查看活动版本与实际状态，失败发布应保留原版本和访问能力 | [开发任务](../roadmap.md) | 产品假设，待用户确认 |
| F6 | 维护者需要及时知道发布失败、执行退出和容量耗尽 | [执行环境设计](../runtime-design.md) | 集成假设，待访谈 |

F1 和 F2 说明平台需要统一控制面与可恢复状态。F3 至 F6 决定非功能需求，后续验收必须使用实际运行时、真实数据库和实际容器。

## 六、访谈问题

1. 请描述最近一次发布服务的过程，从准备材料到外部可以访问分别花了多长时间。
2. 发布过程中查看过哪些工具、文档和日志，哪一步最耗时。
3. 最近一次发布失败或进程退出时，你是如何发现并恢复的。
4. 单台服务器上同时运行多个服务时，你如何确定 CPU、内存和端口不会冲突。
5. 你如何检查不同成员只能访问获授权的项目和资源。
6. 发布失败、容量不足和运行异常时，你希望在多久内收到哪种通知。
7. 哪些现有操作可以交给统一命令，哪些操作必须保留人工确认。
