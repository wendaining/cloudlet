# 第 2 课用户故事与验收标准

本文是软件工程课程设计的第 2 课评审稿，关联任务 [#17](https://github.com/wendaining/cloudlet/issues/17)。故事依据[第 1 课需求调研](lesson-01-requirements-research.md)与《第 2 课需求调研讨论》课程材料形成，验收标准将作为后续接口设计、自动测试和课程评分的依据。

## 检查点

| 提交物 | 结果 |
| --- | --- |
| 用户故事数量 | 24 条，其中功能需求 19 条，非功能需求 5 条 |
| 验收标准 | 每条包含 Given、When、Then |
| Issue 化 | 由任务 [#17](https://github.com/wendaining/cloudlet/issues/17) 跟踪 |
| 负责人 | wendaining |

## 用户角色

| 角色 | 主要目标 | 权限边界 |
| --- | --- | --- |
| 项目所有者 | 管理成员、资源与项目预算 | 可以管理本项目成员和全部资源 |
| 项目开发者 | 发布和操作应用 | 可以创建、修改与停止本项目资源 |
| 项目观察者 | 查看运行情况 | 只能读取获授权的状态、日志和产物 |

## 交付批次

| 批次 | 范围 | 用户价值 |
| --- | --- | --- |
| 基础管理 | 登录、项目、成员、权限与资源状态 | 建立可信的项目边界和统一操作入口 |
| 运行能力 | Workers、Durable Objects、Containers、Browser Run 与 Gateway | 发布真实应用并取得稳定的执行和访问能力 |
| 自动化与恢复 | 恢复、容量、CLI、MCP、Webhook 与管理界面 | 支持脚本、代理、故障处理和生产运维 |

## 用户故事清单

| 编号 | 用户故事 | 类型 | Given | When | Then |
| --- | --- | --- | --- | --- | --- |
| 01 | 作为项目成员，我想登录并保持会话，以便连续管理自己的项目 | 功能需求 | 已有一个启用账号和正确凭据 | 用户提交登录并刷新页面 | 平台建立 HttpOnly 会话，刷新后恢复账号与项目权限，错误密码返回 401 |
| 02 | 作为项目所有者，我想管理成员与角色，以便控制项目访问范围 | 功能需求 | 项目和已有账号均有效 | 所有者添加成员并设置开发者或观察者角色 | 成员取得对应权限，开发者不能修改角色，观察者只能读取 |
| 03 | 作为项目成员，我想查看获授权的资源状态，以便判断运行是否正常 | 功能需求 | 用户只拥有项目 A 的权限 | 用户查询项目 A 和项目 B 的资源 | 项目 A 返回目标状态、实际状态与最近操作，项目 B 被拒绝且不泄露详情 |
| 04 | 作为项目开发者，我想部署 Worker 并从网站访问，以便发布 HTTP 服务 | 功能需求 | 项目具有有效模块包、绑定和兼容配置 | 开发者部署后访问项目域名 | 平台保存不可变版本，启动 workerd，域名返回该 Worker 的预期响应 |
| 05 | 作为项目开发者，我想显式激活 Worker 版本，以便控制流量切换时点 | 功能需求 | 版本 A 正在服务，版本 B 已就绪 | 开发者激活版本 B 并重复提交激活 | 新请求使用 B，域名保持不变，重复激活返回幂等结果 |
| 06 | 作为项目所有者，我想让失败部署保留原版本，以便现有服务持续可用 | 功能需求 | 版本 A 正常服务，版本 B 预检或就绪检查失败 | 开发者部署 B | B 进入失败状态并记录原因，A 继续处理全部公开请求 |
| 07 | 作为外部调用方，我想通过项目域名访问应用，以便获得明确的路由结果 | 功能需求 | 有效域名、未知域名和不可达上游同时存在 | 调用方分别发送请求 | 有效路由完成转发，未知域名返回 404，上游连接失败返回 502 |
| 08 | 作为项目开发者，我想保存 Durable Object 状态，以便跨请求保留业务数据 | 功能需求 | Worker 已绑定有效对象命名空间 | 客户端使用同一对象标识写入后读取 | 读取到已提交值，未提交事务不可见，不同对象标识不会共享状态 |
| 09 | 作为项目开发者，我想并发请求保持数据一致，以便计数和状态机不丢失更新 | 功能需求 | 一个对象保存计数 0，多个客户端并发增量 | 全部并发请求完成 | 最终计数等于成功请求数量，其他对象和项目状态保持不变 |
| 10 | 作为项目开发者，我想启动容器并通过网站访问，以便运行现有 HTTP 服务 | 功能需求 | 镜像摘要、端口、配额和数据卷声明有效 | 开发者创建容器并访问项目域名 | Docker 启动真实容器，健康检查通过后 Gateway 返回预期响应 |
| 11 | 作为项目开发者，我想保留容器数据卷，以便重启或升级后继续使用数据 | 功能需求 | 容器挂载一个已声明的可写数据卷 | 容器写入数据后停止并再次启动 | 新执行读取到原数据，同一可写数据卷只由一个执行写入 |
| 12 | 作为项目开发者，我想停止或删除容器，以便释放资源和清理数据 | 功能需求 | 容器正在运行并持有公开路由 | 开发者停止容器，或删除容器并确认删除数据卷 | 新请求停止，实际资源释放，删除后容器与声明的数据卷不再存在 |
| 13 | 作为项目开发者，我想创建浏览器会话并导航，以便自动执行网页任务 | 功能需求 | 项目凭据有效且容量允许 | 开发者创建会话并打开 HTTP 页面 | 平台启动 Chromium，返回会话端点和与真实页面一致的地址与标题 |
| 14 | 作为项目开发者，我想截取并取得截图，以便保存自动化执行证据 | 功能需求 | 浏览器会话已打开可加载页面 | 开发者请求截图并下载产物 | 平台生成 PNG Artifact，下载内容一致，摘要、大小和项目权限可校验 |
| 15 | 作为项目所有者，我想让浏览器会话到期或关闭后释放资源，以便避免闲置占用 | 功能需求 | 浏览器会话正在运行且容量已经预留 | 会话达到期限，或开发者主动关闭 | Chromium 与容器退出，会话被记录为关闭或失败，容量完成释放 |
| 16 | 作为项目开发者，我想用命令行查询操作结果，以便脚本可靠处理成功与失败 | 功能需求 | 用户已登录并提交一个成功操作或一个无效操作 | 用户查询 Operation 并读取退出状态 | 状态来自管理 API，成功和失败返回文档约定且稳定的退出码 |
| 17 | 作为使用代理工具的开发者，我想通过 MCP 操作授权资源，以便复用统一管理能力 | 功能需求 | MCP 客户端已使用项目有效凭据连接 | 客户端查询资源并发起部署 | 管理 API 完成操作并返回资源与 Operation 标识，代理可以查询同一终态 |
| 18 | 作为项目所有者，我想隔离项目数据与执行资源，以便防止跨项目访问 | 非功能需求 | 两个项目各自拥有 Worker、容器、数据卷和对象 | 使用一个项目的凭据访问另一个项目的管理或执行端点 | 所有跨项目访问被拒绝，网络、挂载、数据与 Secret 均保持隔离 |
| 19 | 作为项目所有者，我想恢复中断的部署，以便重启后得到唯一且明确的结果 | 非功能需求 | 部署已保存产物，但进程在激活前退出 | 控制器恢复并核对元数据与实际执行 | 原版本继续服务，候选执行被接管或清理，Operation 进入明确终态 |
| 20 | 作为项目所有者，我想让控制器重启后接管原容器，以便服务更新不中断运行 | 非功能需求 | 受管理的容器正在运行并持有项目路由 | 管理控制器重启 | 平台按标签与实际状态重新接管同一容器，不创建副本，Gateway 继续转发 |
| 21 | 作为项目开发者，我想更新 Worker 时保留 Durable Object 数据，以便升级不丢失状态 | 非功能需求 | 版本 A 已保存对象数据，版本 B 声明兼容迁移 | 开发者执行 DO 交接并激活 B | 同一对象标识读取到原数据，迁移失败时 A 和原存储继续可用 |
| 22 | 作为项目所有者，我想按四核四 GiB 预算准入资源，以便单机不会超额分配 | 非功能需求 | 已有资源逼近四核四 GiB，多个请求同时申请剩余容量 | 平台执行资源准入 | 成功预留总量不超过预算，超额请求不启动容器，确认清理后释放容量 |
| 23 | 作为项目所有者，我想接收外部失败通知，以便团队及时处理发布和运行问题 | 功能需求 | 项目配置了允许访问的 HTTPS Webhook 端点 | 部署失败、容器异常退出或容量耗尽 | 端点收到带签名、事件标识、资源、时间与错误摘要的 JSON，重试结果可查询 |
| 24 | 作为项目成员，我想同时查看活动版本与实际状态，以便判断平台是否按预期运行 | 功能需求 | 活动版本、目标状态和实际状态存在 | 用户打开资源页面或状态出现不一致 | 界面分别显示活动版本、目标状态、实际状态和最近操作，不混用两类状态 |

## 验收要求

功能需求在主流程之外验证缺少权限、输入无效、依赖失败和资源清理。非功能需求使用真实数据库、真实 workerd、真实 Docker、真实 Chromium 和实际网络请求验证，时间、容量和持久化结果必须可以观测。

故事清单完成不等于实现完成。后续模块 Issue 应引用本文的故事编号，交付时用实际测试证据逐项关闭对应验收场景。
