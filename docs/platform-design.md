# 平台资源与部署设计

本文规定目标架构，作为资源管理、部署、Gateway 和执行模块的实现依据。当前已实现能力见 [架构概览](architecture.md)，运行时规则见 [执行环境设计](runtime-design.md)。

Cloudlet 的产品范围为 Workers、Durable Objects、Containers、Browser Run 和反向代理。管理 API、应用服务与 Gateway 保持在同一个 Go 工程，前端、CLI 和 MCP 使用共享管理 API。

## 资源身份与项目权限

项目是业务资源与授权的边界。CLOUDLET_INSTANCE 标识一套开发或部署环境，一个环境可以管理多个项目。用户通过项目成员关系获得访问权限。

| 模型 | 职责与关键关系 |
| --- | --- |
| Project | 资源与配额归属，使用稳定 project_id |
| ProjectMember | 用户与项目的关系，记录角色 |
| Worker | 稳定的应用身份，关联项目与当前活动 Deployment |
| Deployment | 不可变代码版本，引用产物、运行时版本、绑定与资源要求 |
| RuntimeUnit | 受管理的逻辑执行单元，归属项目，记录其运行要求 |
| Execution | 一次实际执行，记录执行序号、Docker 标识、镜像摘要与观测结果 |
| DurableNamespace | DO 的稳定命名空间，关联类声明、存储标识与执行所有者 |
| Container | 用户容器的逻辑资源，关联不可变配置与实际 Execution |
| BrowserSession | 有过期时间的浏览器会话，关联项目与独立 Execution |
| Artifact | 不可变文件内容，使用 SHA-256 摘要定位 |
| SecretVersion | 凭据值的独立版本，由 Deployment 固定引用 |
| Operation | 部署、启动、停止、删除等操作的过程与最终结果 |

资源名称用于展示，resource_id 用于引用和授权。修改名称、发布版本或更换物理容器保持逻辑资源标识稳定。Execution.generation 是同一执行单元内递增的执行序号。容器名称、IP 地址和端口作为执行观测结果保存。

| 角色 | 权限 |
| --- | --- |
| owner | 管理项目成员、项目资源与项目凭据 |
| developer | 在项目权限和配额内创建资源、发布与操作执行实例 |
| viewer | 查看获授权的资源状态和运行日志 |

平台维护者设置环境级资源上限和执行策略。项目成员权限不能扩大宿主机授权或环境配额。每次资源查询、变更、日志读取和会话连接都验证项目权限。

## 数据与产物归属

| 数据 | 保存位置 | 管理职责 |
| --- | --- | --- |
| 账号、项目、资源、部署、路由、操作与配额记录 | PostgreSQL | 平台元数据与变更事务 |
| Worker 包、部署清单、静态文件与截图 | 平台本地产物目录 | 摘要校验、引用、访问与保留期限 |
| DO 的对象数据与 SQLite 文件 | workerd 的持久化数据卷 | 原生对象存储、事务与一致性 |
| 用户容器数据 | 资源声明的持久化数据卷 | 挂载、权限、备份与删除规则 |
| 浏览器临时配置、下载与运行中状态 | 浏览器会话所属执行环境 | 会话隔离、到期回收与产物导出 |

产物写入经过大小、路径和摘要校验，完整写入并确认持久化后才建立数据库引用。上传失败时删除所属临时文件。保留中的部署、执行实例和已发布产物持有明确引用，清理只删除已经解除引用且达到保留期限的内容。

`internal/artifacts` 提供本地文件存储。调用方提供由平台独占写入的现有目录和单个产物的字节上限。存储按 64 位小写十六进制 SHA-256 摘要读取文件，使用同目录硬链接原子发布。同一摘要的并发写入复用已发布的文件。文件系统须支持硬链接和目录同步。发布后的目录同步或临时文件清理失败会返回错误，重试可以复用已完整发布的内容。

`internal/siteartifact` 从 Artifact 读取 ZIP，并在平台指定的目录下生成静态站点目录。解包前检查成员数量、展开大小、路径和根目录的 `index.html`。返回前同步展开的文件、目录及其父目录。成功后调用方负责管理生成的目录，失败时由本模块清理未完成的目录。显式目录也计入 ZIP 成员上限。

产物读取根据项目内的资源引用执行权限检查。内部存储目录由平台访问，公开静态文件通过所属部署的路由提供。

平台通过成熟归档与文件格式库处理上传内容，拒绝越界路径和超出上限的展开内容。文件目录由平台根据资源标识生成，用户输入不能决定宿主机路径。

容器模块负责把已验证的代码与配置提供给执行卷，运行时按声明以只读方式读取代码。访问 Docker 通过 Engine API，跨 macOS、Linux 和 WSL2 的文件传递需要实际验证。

## 声明与绑定

Deployment 保存代码入口、模块清单、产物摘要、运行时版本、compatibility date、flags、资源要求以及全部绑定声明。Secret 保存为独立引用，运行时控制凭据保存在私有配置中。

绑定包含名称、类型、目标资源标识和允许的操作。部署时验证目标存在、状态可用、项目归属、类型和权限，并将其编译为运行时能够使用的受限服务引用。跨项目绑定被拒绝。

普通环境变量与 Secret 分别管理。Secret 值变更产生独立版本，通过新的部署激活。Secret 密文保存，解密密钥由部署环境提供。管理查询返回 Secret 的名称与元数据，平台日志和部署产物排除其明文。Worker 只能取得自己声明的绑定与 Secret。

Workers、Containers 和 Browser Run 保留各自的执行接口，共享项目身份、权限、操作记录和资源准入。DO 调度与存储由 workerd 执行，平台管理命名空间、绑定和迁移。

## 不可变部署与动态路由

| 阶段 | 处理规则 |
| --- | --- |
| 接收 | 验证身份与请求，建立幂等操作，预留所需容量 |
| 保存 | 写入完整产物与不可变 Deployment，保留运行时及绑定版本 |
| 预检 | 验证模块、绑定、运行时能力、迁移要求与资源预算 |
| 准备 | 创建或复用执行单元，完成对应的就绪检查 |
| 激活 | 验证原活动版本与发布序号，在事务中切换活动版本和路由记录 |
| 收尾 | 更新 Gateway 快照，完成旧执行的排空和资源释放，记录最终结果 |

每个项目的部署变更串行处理。项目的发布序号随激活事务递增，事务检查请求所依据的活动版本和发布序号，过期操作返回冲突。预检失败保留原活动版本和路由。数据库事务、文件系统和 Docker 操作之间通过 Operation 与执行观测记录恢复。

发布成功要求执行单元就绪、绑定可用、路由已生效。就绪检查依据真实运行时响应。HTTP 请求到达时固定使用一份路由快照，活动请求持有对应版本引用，直到完成或达到明确的排空期限。

Gateway 从已提交元数据构建不可变路由快照，在内存中整体替换。上游地址由执行模块提供，业务路由引用资源标识。路由注册检查项目权限与域名、路径冲突，公开请求保持流式转发。

Gateway 记录已经应用的发布序号。数据库已提交而快照尚未生效时，Operation 保持激活阶段，查询分别展示目标版本与实际生效版本。启动接管和状态核对补齐快照，确认生效后才报告发布成功。

涉及 DO 存储所有者更换时，激活还必须完成 [独占交接](runtime-design.md)。相关入口在交接期间可以返回明确的 503。切换历史代码版本前验证当前持久化数据的兼容性，数据恢复单独执行经过验证的恢复流程。

## 生命周期与恢复

资源记录分别描述目标配置、生命周期、实际可用性和最近错误。容器可以处于已创建但已停止状态，生命周期完成与当前运行状态分别展示。BrowserSession 使用有期限的会话状态，关闭后的会话保持终态。

Operation 包含 request_id、operation_id、资源标识、阶段、截止时间和错误信息。幂等键按项目、动作与请求指纹约束。相同执行中请求返回同一操作，键相同而请求不同返回冲突。

成功请求返回已确认结果。确定失败且副作用完成清理后释放预留，保留失败操作记录。执行结果不明时保留资源记录、幂等预留与容量，继续通过实际观测确认。再次执行沿用资源标识，检查已有执行实例。

每个环境只允许一个活动控制器，通过 PostgreSQL 会话锁约束启动接管和资源变更。控制连接失效时停止接收变更、报告就绪失败，执行资源继续运行。

控制器在启动时、收到 Docker 事件后以及定期检查时，核对数据库目标与实际运行时。事件连接恢复后重新检查全部受管理资源。归属检查包含环境、项目、资源、执行序号、镜像及产物引用。处理范围限于平台管理的资源。

| 实际情况 | 处理规则 |
| --- | --- |
| 已运行且符合目标 | 接管原 Execution，恢复端点、路由和会话关联 |
| 已停止且资源要求继续运行 | 验证配置、容量和数据后启动，更新实际端点 |
| 意外退出 | 按配置的次数和总时间上限恢复，超出预算标记失败 |
| 正在创建或删除时后端退出 | 根据资源标识和实际执行结果完成恢复或清理 |
| 观测失败或执行结果不明 | 标记不可用，保留容量和数据，返回具体错误 |
| 缺少元数据的受管理执行 | 隔离调用，记录遗留资源，按明确清理操作处理 |

配置、依赖或能力验证错误立即终止本次操作。每次等待、排空与恢复都有截止时间和终态。删除先撤销新调用和绑定，确认执行结束后释放容量，持久化数据按资源声明删除或保留。

## 资源准入与接口

资源准入同时检查环境和项目的容量，包括运行实例数、内存、CPU、进程数、会话并发与产物空间。预留和释放在元数据事务中执行，执行结果不明的资源继续占用容量。配额调整验证现有预留。

环境预算扣除操作系统、Docker 与固定服务的预留，运行资源按声明的上限申请剩余容量。实际预算通过目标机器上的真实负载验证。

管理界面、CLI 和 MCP 查询同一套资源与 Operation 状态。长操作提供可查询的 operation_id，失败结果包含稳定错误类型和 request_id。接口变更同步更新 OpenAPI 与生成客户端。

能力查询描述实际实现、运行时版本、通过验证的行为和当前可用条件。要求未支持能力的部署返回明确错误。兼容范围和验收要求见 [执行环境设计](runtime-design.md) 与 [测试说明](testing.md)。
